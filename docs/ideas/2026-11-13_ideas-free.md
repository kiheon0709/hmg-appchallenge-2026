# 자유발상 아이디어 (2026-11-13)

리서치 불편에서 출발하지 않고, 차를 다르게 보는 각도에서 넓게 발상한 뒤 제약으로 걸러 낸 목록이에요. 리서치 불편 기반 후보는 `2026-11-13_ideas-mixed.md`에 따로 있어요. 범용 음성 비서형과 음악 선곡형은 처음부터 넣지 않았어요.

**결론부터**: 상위 5개는 ① 숨 쉬는 차(실내 CO₂ 추정·환기) ② 카 이스케이프(차 조작이 입력인 정차 게임) ③ 길동화(경로가 이야기가 되는 뒷좌석 오디오) ④ 차록(차가 스스로 쓰는 일기 겸 이력서) ⑤ 와이퍼 레이더(차들이 느끼는 날씨 지도)예요. 하나만 고르라면 **카 이스케이프**를 권해요. 차량특화성과 기술 활용성이 가장 분명하고, Virtual Console만으로 시연이 끝나요. 숨 쉬는 차는 총점이 1점 높지만 독창성과 재방문 설명이 약해요.

표기: 이 문서의 API 이름은 `docs/pleos-docs/reference/00-INDEX-api-catalog.md`에서 확인한 것이에요. 문서에서 확인하지 못한 것은 **미확인**이라고 적었어요.

8. **깜빡이 코치**: 내비와 방향지시등을 엮는 점은 좋지만 회전 거리 필드가 미확인이고 잔소리로 느껴질 수 있어요.
9. **벨트 히어로**: 귀엽고 간단하지만 에뮬레이터에 벨트 카드가 없어 보여 주기 어려워요.
10. **컨보이**: SDK 5종을 모두 쓰지만 쓰는 날이 1년에 몇 번이고, 두 대를 시연해야 해요.
11. **앰비언트 HUD**: 주행 중 조명 제어 허용이 미확정이라 핵심이 흔들려요.
12. **시트 스트레칭**: 시트 모터를 운동 기구로 보는 점은 새롭지만 끼임 안전과 에뮬레이터에서 안 보이는 것이 문제예요.
13. **서프라이즈 드라이브**: 시연은 화려하지만 한 번 쓰고 끝나요.
14. **차 다마고치**: 급제동을 못 재면 돌봄 항목이 빈약해요.
15. **주차 골프**: 기어가 없어 주차 구간을 정확히 못 잘라요.
16. **빨간불 호흡**: 정차 추정이 거칠고 조명 연출이 미확정이에요.
17. **세차 운세**: 차 데이터가 없어도 거의 같은 답을 낼 수 있어요.
18. **딴길**: 경유지 넣기 말고는 차량 데이터를 쓰지 않아요.
19. **창밖 교실**: 위치 기반 오디오 가이드는 모바일에도 있어요.
20. **드라이브 스탬프 투어**: 모바일 스탬프 투어와 차이가 작아요.

## 4. 상위 5개 상세

### ① 숨 쉬는 차 — 차 안 공기를 대신 챙겨 주는 앱

- **한 줄 소개**: 몇 명이 탔는지, 내기 순환이 얼마나 켜져 있었는지, 창문이 열렸는지로 실내 CO₂ 농도를 추정하고, 졸리기 전에 환기를 권해요.
- **왜 새로운지**: CO₂ 센서가 없는 차에서 이미 있는 신호(착좌·공조·창문·주행 시간)만으로 "가상 센서"를 만들어요. App Market에 차량 데이터가 핵심인 앱이 없다는 빈자리와 맞아요.
- **타깃**: 가족을 태우고 장거리를 가는 운전자, 겨울철 히터를 켜고 출퇴근하는 운전자.
- **핵심 사용 장면**
  1. 넷이 타고 내기 순환으로 40분째 달리는 중. "실내 공기가 답답해졌어요. 외기로 바꿀까요?"라고 한 문장으로 말해요. 화면은 색 막대 하나만 보여요.
  2. 출발 전 P단에서 "오늘은 4명이라 20분마다 2분씩 외기"처럼 환기 계획을 한 번 누르면 정차할 때마다 자동으로 적용해요.
  3. 도착 후 "오늘 주행 중 답답했던 시간 12분" 요약. 휴게소 추천 경유지와 연결해요.
- **쓰는 SDK API**
  - Vehicle: `registerSeatOccupancy`, `registerHvacRecirculationState`, `getHvacFanSpeed`/`registerHvacFanSpeed`, `registerWindowPosition`, `registerHvacPowerState`, `registerTripCurrentDrivingTime`, 제어는 `setHvacRecirculation`·`setHvacFanSpeed`
  - TextToSpeech: `speak`
  - SpeechToText: `request` ("응"/"아니" 한 마디 대답용)
  - NaviHelper: `addWaypoint` (휴게소 경유), 남은 시간은 `onDrivingInfo`·`onTripInfo` (필드 단위 **미확인**)
  - 외기온 읽기 API: 카탈로그에서 찾지 못했어요 → **미확인**. 없으면 외부 날씨 API로 대체
- **에뮬레이터 시연 시나리오**: Virtual Console에서 Seat Occupancy를 4석 Occupied, Air Recirculation을 Recirculate로 → 앱의 추정 막대가 빠르게 올라가요(시연용 배속) → 기준을 넘으면 TTS 권유 → Gear를 P로 두고 "응" → Air Recirculation 카드가 Fresh로 바뀌는 것을 보여 줘요 → Window Position을 30%로 열면 막대가 더 빨리 내려가요.
- **리서치 근거**
  - `user-evidence.md` 6장: 도로공사가 2026년 1~5월 졸음·주시태만 사망자 증가(30명→57명)의 원인으로 히터 사용과 환기 부족에 따른 차내 CO₂ 상승을 지목했다는 보도. 단, 문서에 "원문 재확인 필요" 표시가 있어요.
  - 같은 장: 고속도로 사망사고의 71.5%가 졸음·주시태만.
  - `2026-11-12_driver-research.md` 3-4: 졸음의 우회 방법으로 "창문 열기"가 나와요.
  - `2026-11-12b_senior-novice-pet-commute.md` 3-5: 자동 내기 전환 뒤 김서림이 생겼다는 글 3건. 내기 순환을 오래 두는 것이 불편으로 이어진다는 방향은 같아요.
  - 내기 순환 시 실내 CO₂가 얼마나 오르는지에 대한 수치 근거: **근거 없음**(리서치 문서에 없어요. 외부 논문 확인 필요).
- **가장 큰 위험**: 추정값을 진짜 측정값처럼 보이게 하면 신뢰 문제가 생겨요. ppm 숫자 대신 "쾌적·답답·환기 필요" 3단계로만 보여 줘야 해요. 또 주행 중 공조 제어는 에뮬레이터에서 P단이 아니면 거부된 실측이 있어, 주행 중에는 권유만 할 수 있어요. 순정 차에 비슷한 자동 환기 기능이 있는지도 **미확인**이에요.

### ② 카 이스케이프 — 차가 통째로 컨트롤러인 정차 게임

- **한 줄 소개**: 충전하거나 기다리는 동안, 창문·와이퍼·깜빡이·핸들·문을 실제로 조작해 푸는 방탈출 게임이에요. 다 풀면 글로브박스가 열려요.
- **왜 새로운지**: 화면 속 버튼이 아니라 차의 실물 스위치가 입력이에요. 폰이나 태블릿으로는 만들 수 없어요. 덤으로 신차의 기능을 놀면서 익히게 돼요(27번 "기능 퀘스트" 모드).
- **타깃**: 전기차 충전 대기자, 픽업 대기 부모와 아이, 신차를 막 받은 오너. 2차 타깃은 충전소 사업자와 브랜드(제휴 에피소드).
- **핵심 사용 장면**
  1. 급속 충전 25분. "비밀번호는 오른쪽·왼쪽·오른쪽" 힌트를 듣고 방향지시등을 순서대로 켜요. 맞으면 실내 조명 색이 바뀌고 다음 방으로.
  2. 가족 모드: 차가 문제를 읽고, 좌석별 창문 스위치를 먼저 누른 사람이 답해요(21번 버저 퀴즈). 독서등이 답할 사람 자리에 켜져요.
  3. 기능 퀘스트: "와이퍼를 미스트로 한 번", "뒷좌석 창문 잠금 켜기"처럼 차 기능을 직접 해 보면 체크돼요.
- **쓰는 SDK API**
  - Vehicle 읽기: `registerTurnSignalState`, `registerWindowPosition`, `getCurrentWiperSwitch`(스위치 구독 함수는 없어 주기 조회), `registerWiperState`, `registerSteeringWheelAngle`, `registerBrakePedalStatus`, `registerDoorPosition`, `registerSeatOccupancy`, `registerHighBeamLightState`, `registerWindowLockState`
  - Vehicle 제어(연출·보상): `setAmbientLightBrightnessColor`, `setReadingLightSwitch`, `setGloveBoxLock`
  - TextToSpeech: `speak`, `setAudioZoneId`(좌석별 힌트. zoneId 값 체계 **미확인**)
  - SpeechToText: `request` (말로 답하는 퍼즐)
  - 매니페스트 `android:appCategory="game"`
- **에뮬레이터 시연 시나리오**: Gear P. Virtual Console에서 Turn Signal State를 우→좌→우 → 1번 방 통과, Ambient Color 카드 색이 바뀌는 것 확인 → Windshield Wiper Switch를 High, Steering Angle을 90도로 → 2번 방 통과 → Window Position 뒷좌석 좌를 0%로 내려 버저 → 정답 → Glove Box 카드가 열림으로 바뀌어요. Gear를 D로 바꾸면 게임이 멈추고 가려지는 것까지 보여 줘요(주행 규제 준수).
- **리서치 근거**
  - `2026-11-12_dc-pleos-reactions.md`: "화면만 커졌지 쓸 이유가 없다"는 반응이 중심이고, 차 상태 정보를 못 찾겠다는 글이 클리앙과 디시 양쪽에 있어요(기능을 모른다는 신호).
  - `2026-11-12_driver-research.md` 4장 세그먼트 공통점: "주차된 차 안에서 보내는 시간"이 부모·직장인·업무 운전자·전기차 오너에 모두 걸쳐요.
  - `docs/pleos-docs/00-contest-and-ecosystem.md` 4절: App Market 확대 예정 카테고리에 게임이 있어요.

### ③ 길동화 — 오늘 가는 길이 이야기가 돼요

- **한 줄 소개**: 목적지와 남은 시간, 지나는 길에 맞춰 도착할 때 딱 끝나는 동화를 만들어 뒷좌석에만 들려줘요.
- **왜 새로운지**: 이야기의 길이와 사건이 실제 경로에서 나와요. 남은 시간이 20분이면 20분짜리 이야기, 큰 우회전이 다가오면 "용이 오른쪽으로 크게 돌아요"가 먼저 나와요(커브 예고가 멀미 큐를 겸해요). 화면을 쓰지 않아 주행 규제와 부딪히지 않아요.
- **타깃**: 3~8세 아이를 태우고 혼자 운전하는 부모. 등하원·주말 나들이·명절 장거리.
- **핵심 사용 장면**
  1. 출발 전 P단에서 주인공만 고르고 출발. 뒷좌석에 아이가 앉아 있으면(착좌) 이야기가 뒷좌석 스피커로만 나오고 운전석은 내비 안내가 그대로 들려요.
  2. 아이가 "언제 도착해?"라고 하면 부모가 핸들 옆 버튼 한 번 → "이야기 두 장면 남았어"라고 이야기 속 단위로 답해요.
  3. 정체로 도착이 10분 늦어지면 이야기에 곁가지 장면이 하나 늘어나요. 도착 이벤트에 맞춰 결말.
- **쓰는 SDK API**
  - NaviHelper: `getDestinationInfo`, `getRouteStateInfo`, `getTBTInfo`(→ `onTBTInfo`, 필드 **미확인**), `onDrivingInfo`·`onTripInfo`(남은 시간, 단위 **미확인**), `onDestinationArrived`, `onWayPointArrived`
  - TextToSpeech: `speak(text, isFinal)`, `setAudioZoneId`(뒷좌석 존 값 **미확인**), `setSpeakerType`
  - SpeechToText: `request` (아이의 선택지 대답 "용!" "토끼!")
  - Vehicle: `registerSeatOccupancy`(뒷좌석 탑승 판단), `registerWiperState`(비 오는 날은 비 오는 이야기), `registerDoorPosition`
  - FusedLocation: `registerFusedLocationCallback`, `addProximityAlert`(다리·터널 같은 지점 사건)
  - 외부 LLM(텍스트만): 장면 단위로 미리 생성해 두어 주행 중 CPU 부담을 피해요
- **에뮬레이터 시연 시나리오**: Seat Occupancy 뒷좌석 좌를 Occupied → 앱에서 주인공 선택 → `requestRoute`로 목적지 설정 → 남은 시간에 맞춘 장면 수가 화면에 표시되고 TTS가 시작 → Windshield Wiper Switch를 Low로 바꾸면 다음 장면에 비가 내려요 → 도착 이벤트로 결말. 에뮬레이터에서 경로 주행과 위치를 움직이는 방법은 문서에 없어 **미확인**이에요. 안 되면 남은 시간 값을 디버그 입력으로 넣어 시연해요.
- **리서치 근거**
  - `2026-11-12_driver-research.md` 3-2: 아이 울음이 운전자 안전과 직결되고("이성을 잃을 뻔"), 10년 넘게 우회 방법이 동요·영상이에요. 영상은 멀미를 악화시킨다는 의견이 같은 글에 있고, "끝말잇기 등 놀이하며 가면 괜찮다"는 댓글이 있어요.
  - `2026-11-12b_parents-women-drivers.md` 6절: 차에서 태블릿 보여 주기 논쟁 글(조회 12K·댓글 172), 화면 대신 소리만 들려주자는 부모가 있어요. 3-4: 아이 멀미.
  - `2026-11-12_in-car-agent-domain.md` 4.5: 뒷좌석의 핵심 문제는 지루함이고 글을 못 읽는 아이를 고려해야 한다는 연구(Wilfinger 2011).
  - 커브를 미리 알려 주면 멀미가 준다는 근거: **근거 없음**(리서치 문서에 없어요. 넣으려면 외부 확인 필요).
- **가장 큰 위험**: 아이용 생성 콘텐츠의 품질과 안전성이에요. 매번 새로 만든 이야기가 재미없거나 부적절하면 한 번에 신뢰를 잃어요. 검수된 이야기 뼈대에 지명·시간·날씨만 끼워 넣는 방식으로 좁혀야 해요. 좌석별 오디오 존이 실차 차종마다 되는지도 확인이 필요해요.

### ④ 차록(車錄) — 차가 스스로 쓰는 일기, 팔 때는 이력서

- **한 줄 소개**: 누가 탔는지, 비가 왔는지, 어디를 다녀왔는지, 경고등이 언제 켜지고 꺼졌는지를 차가 알아서 적어요. 평소에는 일기로 읽고, 차를 팔 때는 믿을 수 있는 이력서로 내보내요.
- **왜 새로운지**: 주행 기록 앱은 "거리와 연비"를 적지만, 이 앱은 차만 아는 사건(문이 몇 번 열렸는지, 뒷좌석에 누가 앉았는지, 와이퍼를 켰는지)으로 문장을 만들어요. 운전자가 아무것도 입력하지 않아요.
- **타깃**: 신차 오너 전체(백그라운드로 쌓임). 수익 쪽 타깃은 중고차 플랫폼과 보증 사업자.
- **핵심 사용 장면**
  1. 주말 여행에서 돌아와 P단. "셋이서 214km, 오는 길엔 비. 뒷좌석 왼쪽은 내내 창문을 열고 있었어요." 한 줄을 말로 덧붙이면(STT) 일기가 완성돼요.
  2. 타이어 압력 경고가 켜졌다가 이틀 뒤 꺼짐. 차록에 "경고 → 조치 완료"로 남고, 조치 내용을 한 마디로 적어 둘 수 있어요.
  3. 3년 뒤 판매. "경고등 이력 4건 모두 7일 안에 해소, 주행의 62%가 1인 탑승" 같은 리포트를 QR로 구매자에게 보여 줘요(정차 중).
- **쓰는 SDK API**
  - Vehicle: `getVINInfo`, `getCurrentDistanceDriven`·`registerDistanceDriven`, `getTripCurrentDrivingDistance`, `getTripCurrentDrivingTime`, `registerTelltales`·`getTelltalesInfo`, `getLowTirePressure`, `hasLowWasherFluidWarning`, `getEngineOilLevelState`, `registerSeatOccupancy`, `registerDoorPosition`, `registerWiperState`, `registerWindowPosition`, `getCumulativeFuelEconomy` 또는 `getCumulativeEvEfficiency`, `registerEvBatteryStateOfCharge`
  - NaviHelper: `getDestinationInfo`, `onDestinationArrived`
  - FusedLocation: `getLastKnownLocation`
  - SpeechToText: `request`(한 줄 메모), TextToSpeech: `speak`(도착 요약 낭독)
  - 외부 LLM(텍스트): 사건 목록을 문장으로
- **에뮬레이터 시연 시나리오**: Virtual Console에서 Seat Occupancy 3석, Door Position 열림/닫힘, Windshield Wiper Switch Low, Odometer +214, Telltales의 TPMS를 On → Off 순서로 조작 → Gear P → 앱이 오늘의 일기 한 단락과 "경고등 1건 해소"를 보여 주고 읽어 줘요 → 미리 넣어 둔 3년 치 예시 데이터로 이력서 화면을 보여 줘요.
- **리서치 근거**
  - `2026-11-12_dc-pleos-reactions.md`: 배터리 전압·엔진오일 양을 어디서 보는지 모르겠다는 글. 차 상태 정보를 찾기 어렵다는 신호가 클리앙·디시 양쪽에서 나와요.
  - `2026-11-12_driver-research.md` 3-14(차량 관리: 경고등·정비) 절이 있어요. 이 문서를 쓰면서 본문까지 대조하지는 않았어요.
  - 중고차 이력 신뢰, 드라이브 기록 수요: **근거 없음**.
- **가장 큰 위험**: 급한 불편이 아니에요. "있으면 좋은 것"으로 읽히면 창의성 항목에서 밀려요. 또 탑승 인원과 위치 기록은 개인정보라 저장 범위와 내보내기 동의를 분명히 해야 해요. Pleos 탑재 차가 신차뿐이라 이력서의 가치는 몇 년 뒤에야 생겨요(그래서 일기가 당장의 가치여야 해요).

### ⑤ 와이퍼 레이더 — 차들이 느끼는 날씨

- **한 줄 소개**: 앞서가는 차들의 와이퍼·안개등·성에 제거 상태를 모아, 내 경로 앞 몇 km에 실제로 비·안개·김서림이 있는지 알려 줘요.
- **왜 새로운지**: 기상청 예보가 아니라 지금 그 길 위의 차들이 겪는 상태예요. 와이퍼를 강수 센서로, 안개등을 안개 센서로 써요. 차량 데이터가 없으면 존재할 수 없는 서비스예요.
- **타깃**: 고속도로 장거리 운전자, 비 오는 밤 운전이 무서운 초보. 데이터 쪽 고객은 도로 관리 기관과 내비 사업자.
- **핵심 사용 장면**
  1. 맑은 구간을 달리는 중. "8km 앞부터 앞차들이 와이퍼를 세게 켜고 있어요." 한 문장.
  2. 비가 오는데 내 전조등이 꺼져 있으면(오토라이트 미작동) "주변 차들은 전조등을 켰어요"라고 알려요.
  3. 출발 전 P단에서 경로 위 구간별 상태를 색 띠 한 줄로 확인. 심하면 휴게소를 경유지로.
- **쓰는 SDK API**
  - Vehicle: `getCurrentWiperSwitch`(주기 조회), `registerWiperState`, `registerFrontFogLightState`, `registerRearFogLightState`, `registerLowBeamLightState`, `registerHvacDefrosterState`, `getHvacMaxDefrostState`
  - FusedLocation: `registerFusedLocationCallback`(위치·방향. 방향 필드명 **미확인**)
  - NaviHelper: `getRouteStateInfo`(경로 위 구간 대조. 경로 형상을 주는지 **미확인**), `onCautionPointInfo`, `addWaypoint`
  - TextToSpeech: `speak`
  - 외부 서버: 익명 집계(구간 단위, 차량 식별값 없이)
- **에뮬레이터 시연 시나리오**: 서버에 가상 차량 200대의 와이퍼 상태를 흘려 두어요 → 앱이 "8km 앞 강한 비"를 말해요 → Virtual Console에서 내 차의 Windshield Wiper Switch를 High로 바꾸면 서버 지도(PC 화면)의 내 구간 색이 바뀌는 것을 나란히 보여 줘요 → Exterior Lights Mode가 Off인 상태에서 등화 알림이 나와요. 위치 주입 방법은 **미확인**이라 내 위치는 고정값으로 시연해요.
- **리서치 근거**
  - `2026-11-12_dc-pleos-reactions.md`: Pleos에 기대한 것으로 "같은 차량끼리 실시간 교통 공유"를 든 글이 있어요.
  - `2026-11-12_driver-research.md` TOP 15의 10번: 비·안개 속 후미등 미점등, "꺼진지 모르는 겁니다"(조회 3,865·댓글 41).
  - `2026-11-12b_senior-novice-pet-commute.md` 3-4·3-5: 빗길 야간 치사율(100건당 2.0명), 결빙 사고의 54%가 눈·비 없는 날, 20초 만에 앞유리 김서림 글.
  - 같은 문서 1-3: 폭우·폭설 운전 후기 원문은 약하다고 적혀 있어요.
  - 와이퍼를 강수 센서로 쓴 선행 연구: **근거 없음**(리서치 문서에 없어요. 외부 확인 필요).
- **가장 큰 위험**: 이용 차가 적으면 지도가 비어요. Pleos 탑재 차가 막 나오기 시작한 지금은 밀도가 안 나와요. 기획서에서는 "차 한 대만 있어도 쓸모 있는 기능"(등화 알림, 내 주행의 날씨 기록)을 먼저 세우고 군집 지도는 확장으로 두어야 해요. 서버까지 만들어야 해서 마감까지의 개발량도 가장 커요.

## 5. 판단에 쓴 사실과 남은 확인

- Virtual Console에 있는 카드: 기어, 브레이크, 조향각, 문, 창문, 착좌, 와이퍼 스위치, 방향지시등, 앰비언트, 공조, 글로브박스, 경고등 등. **없는 것**: 차속, 위치·경로 주행, 안전벨트(경고등만 있음). 시연 점수는 이 기준으로 매겼어요 (`docs/pleos-docs/02-dev-environment-and-guides.md` 2.2~2.3).
- 에뮬레이터 실측(11/07): P단이 아니면 제어(set)가 `ERROR_DRIVING_RESTRICTED`(50001)로 거부됐어요. 앰비언트는 D단에서 set이 성공한 기록도 있어 실차 허용 여부는 미확정이에요 (`docs/STATUS.md`, `03-sdk-usage-guides.md`).
- 미확인 목록: TTS `setAudioZoneId`의 좌석별 zoneId 값, `onTBTInfo`·`onDrivingInfo`·`onTripInfo`의 필드와 단위, FusedLocation 콜백의 방향 필드명, 외기온 읽기 API 유무, 시트 위치 값의 단위, 에뮬레이터에서 위치·경로 주행을 재현하는 방법.
- 6위 이하에서 눈여겨볼 것: **컨보이**는 SDK 5종을 모두 핵심에 쓰는 유일한 후보예요. 사용 빈도 근거가 생기면 다시 볼 만해요.
