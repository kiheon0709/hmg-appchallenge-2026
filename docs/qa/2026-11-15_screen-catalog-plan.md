# 타비(TABI) 화면 도감: 찍을 화면 목록 (2026-11-15)

타비의 모든 기능과 모든 경우의 화면을 캡처해 노션에 정리하기 위한 목록이에요. 평가가 아니라 기록이에요. 이 문서는 1단계(목록 만들기) 결과이고, 캡처는 시작 신호를 받은 뒤에 해요.

- 기준 소스: 커밋 `b2770aa`(v20). 온보딩은 다른 세션이 만드는 중이라 아직 소스에 없어요.
- 읽은 것: `docs/STATUS.md` 맨 위 절, `docs/qa/`의 기능 점검 계획·보고서와 UX 평가, `core/`의 상황·코치·리뷰·가는 길 추천 정의, `app/.../ui/`의 화면, `DebugCommands.kt`, `DebugPanel.kt`.
- 캡처 위치: `docs/qa/shots-catalog/`. 파일 이름은 `절번호_기능_경우_land|port_day|night.jpg`(예: `E03_suddenstop_braked_land_night.jpg`).

## 띄우는 방법 표기

| 표기 | 뜻 |
| --- | --- |
| **R** | release APK에서 화면 터치만으로 |
| **RV** | release APK + 차량 신호(Virtual Console). 차량 신호가 꺼져 있으면 아래 DP로 대신해요 |
| **D** | debug 빌드의 adb 명령: `adb shell am broadcast -a io.moodlab.sideseat.DEBUG --es cmd <명령> --es arg <값>` |
| **DP** | debug 빌드의 디버그 패널(`action ToggleDebugPanel`)로 신호를 넣음. 먼저 `vehicle debug`. 패널에 있는 것: 와이퍼, 전조등, 상향등, 안개등, 깜빡이, 비상등, 브레이크, 성에 제거, 에어컨, 내기순환, 운전석 창문, 주차 브레이크, 공기압 경고등, 정차(P)/주행, 제한속도(없음·30·50·80), 테마, 핸들 각도 |
| **G** | 에뮬레이터 위치 넣기(`adb emu geo fix`): 보호구역 좌표, 좌표를 1초마다 옮겨 속도 만들기 |
| **P** | 녹음 파일로 묻기: `ask_pcm`(질문하기), `wake_pcm`(호출어). 16 kHz 16 bit mono PCM을 앱 files 폴더에 넣어야 해요. 맥의 `say`와 `ffmpeg`로 만들 계획이에요 |
| **N** | 인터넷과 LLM 키가 있어야 나오는 것. 키는 `local.properties`에 있고 저는 읽지 않아요. debug 빌드에 키가 들어가 있으면 나오고, 아니면 "찍지 못함"으로 남겨요 |
| **T** | 조건을 만드는 데 오래 걸림(괄호 안이 기다리는 시간) |
| **?** | 띄울 수 있을지 불확실. 2단계에서 시도하고 안 되면 이유를 적어요 |

화면 내용은 debug와 release가 같아요. release로 되는 것은 release로 찍고, 나머지는 debug로 찍어 파일 이름에 `_debug`를 붙여요. qa-audit 세션의 `docs/qa/shots-coach/`(주행 코치·리뷰)는 같은 빌드의 것이면 가져다 쓰고 출처를 적어요.

기본은 가로·야간이에요. "주간", "세로"라고 적은 것만 따로 찍어요.

## E. 상황별 (85)

소스의 상황은 19개예요. "앞유리 이물질"은 꺼 둔 상황이라 챕터와 교관 대결 판에 없어요(`inject WIPER_DEBRIS`로 뜨면 찍고, 안 뜨면 이유를 적어요). 나머지 18개가 다섯 챕터에 들어 있어요.

띄우는 방법은 모두 같아요: release에서는 그 챕터를 시작해 차례를 기다리고(터진 순간까지는 R), 조작 도중과 성공은 차량 신호(RV)나 디버그 패널(DP)이 필요해요. debug에서는 `action StartVersus` 뒤 `inject <이름>`으로 바로 띄워요. 선택지는 화면 버튼이나 `answer <문장>`.

## 2단계 진행 순서

1. 에뮬레이터 cold boot, Virtual Console이 되는지 확인. 되면 release에서 차량 신호로, 안 되면 debug의 디버그 패널로.
2. release를 새로 설치해 A(첫 실행) → B(처음 홈) → D의 R 항목 → E의 질문형 상황(E08, E09, E19) → F의 R 항목.
3. 같은 커밋의 debug 빌드로 바꿔 D·E의 조작 화면, C(가는 길), F의 나머지, G(녹음 파일), H, I.
4. 주간 테마와 세로 창.
5. 시간이 오래 걸리는 것(H06, H09, H12)은 맨 뒤에 몰아서.
6. 노션 "타비 화면 도감" 정리. 이미지를 올릴 수 없으면 `docs/qa/2026-11-15_screen-catalog.md`에 정리.
7. 계획·캡처·문서 로컬 커밋, 에뮬레이터 종료.
