### 소리를 확인한 방법과 한계

- 앱 쪽: 효과음은 `sfx play name=<이름>`, 음성은 `tts speak` → `tts start` → `tts done` 로그로 재생 요청과 시작·끝을 확인했어요
- 기기 쪽: `dumpsys audio`에서 앱의 SoundPool 재생기(uid 1010224, `USAGE_GAME`, piid 239)가 `event:started`를 10번 남긴 것과, Pleos TTS의 AudioTrack(uid 1010143, `USAGE_ASSISTANT`)이 말할 때마다 새로 만들어져 `started`→`stopped`된 것을 확인했어요. 오디오 포커스도 `MediaFocusControl`에 요청·반납이 기록돼요
- **음질, 크기, 말투의 자연스러움은 판단하지 않았어요.** 재생됐다는 기기 쪽 기록까지만 확인했어요
- 이번 점검에서 한 번도 재생되지 않은 효과음: `wiper`, `wind`, `chime`, `tick` (파일은 있으나 앱 코드에서 부르지 않음)

## 심각도별 문제 목록

### 치명 (기능이 안 됨·크래시)

**1. 주행 중 코치 화면이 시스템 차단 화면에 가려요** — 상태(14:10): **수정본 `ffce21f`에서 해결 확인.** 새 설치(권한 허용·거절)와 `-g` 설치, 훈련 도중 D, 재시작 뒤 D에서 모두 코치 화면이 보였어요(아래 "재확인 2차")
- 현상: Gear D가 되면 앱은 코치 모드로 바뀌지만(로그 `app mode HOME -> COACH`), 화면에는 시스템의 "주행 중에는 사용할 수 없습니다." 화면이 덮여요. 한 줄 안내, 신호 3개, "질문하기" 버튼, 호출어 안내가 모두 보이지 않아요. 화면 구조(uiautomator)에는 코치 화면 글자가 그대로 있어요
- 음성 코치는 동작해요: K01·K02·K06·K11·K12의 말이 TTS로 재생됐어요. 호출어("타비야")로 묻는 것도 돼요(debug에서 확인)
- 재현: release APK를 `adb install`로 설치 → 홈 → Virtual Console Gear D
- 증거: `shots/G1_coach.jpg`, `shots/G3_coach_k01.jpg`, `shots/G15_background.jpg`
- 참고: 매니페스트에 `distractionOptimized=true`가 있어요. adb로 설치한 앱이라 시스템이 주행 중 허용 앱으로 보지 않는 것인지는 이번 점검으로 가리지 못했어요

### 중요 (사용자가 막히거나 오해함)

**2. 리뷰의 "지금 1분만 연습할까요?"를 누르면 교관 대결 화면에 남아요**
- 현상: 권한 상황(폭우)을 마치면 결과나 홈으로 가지 않고 "교관 대결 · 평온한 주행"과 상황 버튼 판이 떠요. 끝내는 길은 "그만하기"뿐이에요
- 재현: 주행 → P → 리뷰에서 "지금 1분만 연습할까요?" → 상황을 마침
- 증거: `shots/H5_after_one_minute.jpg`, 로그 `app training VERSUS HEAVY_RAIN SUCCESS` 다음 `VERSUS null CRUISE`

**3. 교관 대결 상황 판의 버튼 3개가 화면 밖이고, 꺼진 상황이 들어 있어요**
- 판이 스크롤되지 않아 19개 가운데 16개만 보여요. 화면 밖 3개는 누를 수 없어요(소스 순서상 수막현상·일반 차로 요금소·하이패스 차로 오진입 쪽)
- 쓰지 않는 상황 "앞유리 이물질"이 판에 있어요. 누르면 "그 상황은 이 차에서 아직 연습할 수 없어요."만 나와요(로그 `Inject(situation=WIPER_DEBRIS)`)
- 이름이 잘려 "고속도로 …" 버튼 두 개(고장·합류)를 구별할 수 없어요
- 재현: 홈 → 교관 대결
- 증거: `shots/E5_versus_board_scrolled.jpg`

**4. 앞차 급정거의 반응 시간 표시가 브레이크 뒤에도 계속 올라가요**
- 브레이크를 밟은 뒤 "비상등 켰나요?"를 기다리는 동안 링의 "반응 시간"이 계속 올라가 579.86까지 갔어요. 성공 화면에서는 링이 1.5, 카드가 "0.0초 걸렸어요"로 서로 달라요
- 같은 동안 화면 속 속도가 다시 80km/h로 올라가요(앞차 뒤에 멈춘 장면인데)
- 재현: C1 → 앞차 급정거 → BRAKE → 비상등 질문에 답하지 않고 기다림
- 증거: `shots/C3_suddenstop_hazardq.jpg`(579.86, 80km/h), `shots/C3_suddenstop_braked.jpg`(0.85), `shots/C3_suddenstop_success.jpg`(링 1.5 / 카드 0.0초)

**5. 홈 추천 이유가 사실과 달라요**
- 모든 챕터에 별이 있는데 "오늘의 추천 · 첫 빗길 / 아직 별이 없는 챕터예요."라고 나와요(`shots/A_home_after_all.jpg`)
- 0분짜리 주행(아무 말도 하지 않음) 뒤에 "지난 주행에서 맞은편 눈부심 상황이 있었어요."라고 나와요. 밤에 달렸다는 것만으로 권한 것이에요(`shots/L13_after_restart.jpg`, 로그 `review summary min=0 … said=0`)
- 리뷰에서 권한 상황을 바로 연습한 뒤에도 같은 추천 이유가 남아요(`shots/H6_home_recommend_after_review.jpg`)

**6. 훈련 중 Back 키를 누르면 이어 하기 지점이 사라져요**
- "그만하기"는 홈에 "이어서 하기 · 첫 빗길"을 남기지만, Back 키는 `GoHome`만 하고 훈련을 중단 처리하지 않아 홈이 "오늘의 추천"으로 돌아가요. 진행 기록 저장도 하지 않아요. 소리는 둘 다 멈춰요
- 재현: 챕터 시작 → 상황 진행 중 Back 키
- 증거: 로그 `app action GoHome` → 홈 텍스트 "오늘의 추천 | 밤 고속도로"(같은 조건에서 `AbortTraining`은 "이어서 하기")

### Gear D를 못 만든 이유

- 에뮬레이터를 cold boot로 네 번 띄웠어요(한 번은 `-dns-server 1.1.1.1,8.8.8.8`). 네 번 모두 `eth0`에 IPv4가 없었어요(`ifconfig eth0`에 `inet addr` 없음, IPv6 링크 주소만). 차량 HAL이 `sdv_vhal_rust: network eth0 is not ready yet`을 0.2초마다 남기고, Virtual Console은 `{"error":"emulator_inactive"}`, `bridge_ready=false`, `dds_ready.all=false`였어요
- **지난 점검 때의 심장박동 문제와는 달라요.** 심장박동을 보내도 `/browser/session` 응답이 `"active":false`였어요. 콘솔의 신호 다리(DDS)가 eth0 위에서 뜨는데 그 망이 없는 상태예요
- eth0를 설정하는 `netconfig` 서비스는 `service.netconfig.done=1`(끝남)인데도 주소가 없고, `dumpsys ethernet`에는 `IpClient is null`이에요. 에뮬레이터가 `user` 빌드라 다시 돌릴 수 없고 `cmd car_service inject-vhal-event`도 막혀 있어요(`requires non-user build`). Wi‑Fi를 꺼도 달라지지 않았어요(다시 켜 둠)
- (2차에서 바로잡음: 원인은 맥 네트워크가 아니라 첫 점검의 `svc data disable`이었어요.) 지난 점검(02:55 부팅)에서는 같은 명령으로 차량 신호가 살아 있었어요. 지금 맥의 네트워크가 `en0 192.0.0.2`, 라우터 `192.0.0.1`(IPv6 위주 망으로 보임)이라 그때와 다를 가능성이 커요. 맥 설정은 건드리지 않았어요. 일반 IPv4 Wi‑Fi에 다시 연결한 뒤 cold boot하면 살아날 수 있어요(추정)
