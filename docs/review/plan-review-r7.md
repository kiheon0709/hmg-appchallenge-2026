## 6. 판정: SDK 없이 도달 가능한 최대 점수와 4.0까지의 최단 경로

- **SDK·APK·영상 없이 최대 약 3.7.** W2의 문서·core 부분(감지 범위 표, 비 오는 중 터널 보조 규칙, 피날레·크루징 오버레이, 앱 일몰 계산), W3(앵커 1개, 내재화 출구, KPI 재정렬, 연도별 모수), W4(문맥 기반 휴게소 판정과 회귀 15문장, 수락 후 안내), W5를 모두 반영한다는 가정입니다. 축별 예상은 차량특화성 3.7, 창의성 3.6, 기술활용성 3.6, 사업성 3.9이고, 평균은 약 3.70입니다. 기술활용성은 "SDK 호출 0"이 상한을 정하므로 core를 아무리 다듬어도 3.6~3.65를 넘기 어렵습니다. 이번 바퀴(+0.02)가 보여 주듯, 문서와 core로 올릴 여지는 거의 소진됐습니다.
- **4.0에 필요한 최단 실증 목록 (위 문서·core 수정과 함께)**
  1. **Pleos 에뮬레이터에서 Wiper·LowBeam 실제 구독 → 앱 장면 전환.** 날짜, 단계 값(INT/LOW/HIGH 구분 여부), 기어 신호 출처를 5-2에 기록합니다. 이것만으로 차량특화성과 기술활용성이 각각 약 +0.2입니다.
  2. **앰비언트 set을 P단과 D단에서 1회씩 호출한 결과(성공 또는 에러 코드).** F3를 "추정"에서 "확인"으로 바꿉니다.
  3. **Virtual Console과 앱을 나란히 찍은 20~30초 영상.** 와이퍼 → 비 장면 → 곡·화면 색 전환, 가능하면 P단 → 조명 적용까지 담습니다.
  4. **에뮬레이터에 설치해 실행한 release APK**(`apk/MoodLab_MooDrive_release.apk`). 가산점 항목을 채우고 "Android 실빌드 미확인"을 없앱니다.
- 1~4가 있으면 기술활용성 3.9~4.0, 차량특화성 3.9 전후, 사업성 3.9, 창의성 3.6으로 평균 약 3.85~3.95입니다. 확실히 4.0을 넘으려면 다음 중 하나가 더 필요합니다. 하나는 NaviHelper ETA 1회 수신이고(피날레가 실제 내비와 맞물린다는 증거), 다른 하나는 정체 위 피날레 오버레이 같은 W2 core 수정입니다. 마감까지 12일 남았고 SDK 신청부터 해야 하므로, 오늘 신청하는 것이 가장 시급합니다.
