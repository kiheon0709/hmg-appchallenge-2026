- 리뷰 대상: `기획서_초안.md`, `docs/research/user-evidence.md`, `docs/screens/*.png` 8장(전부 확인), `core/` 소스·테스트, `app/src/main/**`, `README.md`, `docs/STATUS.md`
- 기준: 1차 서류심사 4축(차량특화성·창의성·기술활용성·사업성)과 가산점(프로토타입/GitHub/APK). 4.0은 "지적을 고쳤다"가 아니라 "상위권 출품작 사이에서도 눈에 띈다"는 뜻입니다.
- 검증 방법
  - `./gradlew :core:test` 통과: **55개**(ContextEngine 13, Session 31, DemoTrace 8, Genres 2, VoiceCommand 1). 실패 0. 기획서·STATUS의 "55개"와 일치합니다.
  - `tools/app-compile-check`에서 `compileKotlin` 통과. 스텁 기반이라 Android 실빌드나 APK를 증명하지는 않습니다.
  - 저장소 파일은 이 리뷰 외에는 수정하지 않았습니다. 스크래치 디렉터리에 별도 Gradle 프로젝트를 만들어 저장소의 `core/src/main` 소스를 그대로 참조하고 탐침 테스트를 돌렸습니다. 아래 "탐침" 수치는 모두 그 실행 결과입니다.
- 이전 리뷰 점수(2.8, 2.9, 3.1)는 참고하지 않고 새로 매겼습니다. 이전 리뷰는 해소 여부를 확인하는 데만 썼습니다.

## 1. 점수표

| 축 | 점수 | 근거 |
|---|---|---|
| 차량특화성 | **3.6** | "와이퍼·전조등·기어·연속 운전 시간은 차만 안다"는 논리와 Gemini 비교 행이 들어가 "왜 폰이 아니라 차인가"는 이제 서류만으로도 설득됩니다. 하지만 그 논리를 받치는 신호 판정이 실제 주행에서 흔한 상황에 약합니다. 오토라이트를 켠 채 비가 그치면 4분 동안 '터널'로 판정되고(탐침), 1분짜리 P단 정차마다 "도착했어요"와 드라이브 카드가 뜹니다. 차에서만 되는 출력인 주행 중 앰비언트는 여전히 기본 꺼짐입니다. |
| 창의성 | **3.4** | 경로를 앨범 하나로 보는 발상, 도착 피날레, 터널 침묵, 장면 위에 겹치는 휴식 경보는 일관된 하나의 콘셉트입니다. Android Auto + Gemini와의 차이("말할 필요조차 없음")도 표에 정리됐습니다. 다만 본질은 "Songza·Climatune + 차량 신호 + 조명"이라서, 상위권을 가르는 비약적 요소(Gleo와 연계한 장면 신호 공급, 동승자 인식 등)는 여전히 확장 목록에만 있습니다. |
| 기술활용성 | **3.1** | 이전 최대 결함(이벤트 방식 신호에서 디바운스가 끝나지 않음)은 `tick()`과 ViewModel의 1초 틱으로 고쳤고 테스트도 있습니다. 템포 상한 우선, 휴게소 1분 시간 초과도 탐침으로 확인했습니다. 그러나 Pleos SDK 호출은 여전히 0개이고 APK·영상·Media3도 없습니다. 탐침에서는 세션 수명 결함이 새로 나왔습니다. 데모를 두 번 재생하면 대표 멘트 "비가 오기 시작했네요"가 빠지고, 주행 로그가 계속 쌓여 두 번째 카드에 첫 주행 장면이 섞입니다. 피날레 뒤에 곡이 또 이어지고, 의미를 반대로 해석하는 음성 문장도 남아 있으며, 테스트 하나는 아무것도 검증하지 않습니다. |
| 사업성 | **3.0** | "누가 왜 돈을 내나", 모방 대응, 대량 태깅 계획, MAU 모수가 '상한'이라는 단서가 들어가 구조는 갖췄습니다. 그러나 300원·KPI·퍼널 비율은 모두 근거 없는 가정치이고, 기준 시나리오 매출이 연 3.2억 원이라 사업 규모 자체가 작습니다. 1단계(로열티프리 자체 재생)에서 사용자가 멜론 대신 MooDrive를 켤 이유와, Gleo·멜론이 장면 규칙을 내재화할 때의 방어(데이터·계약)는 여전히 비어 있습니다. |
| **평균** | **3.3** | (3.6 + 3.4 + 3.1 + 3.0) / 4 = 3.275. 정직성과 문서 정합성은 상위권 수준입니다. 4.0까지 가려면 ① 차 신호를 실제로 받은 장면 하나(영상 또는 기록), ② 실제 도로 상황에서 오탐이 적은 판정 규칙, ③ "1단계에서도 살아남는" 사업 구조, 이 세 가지가 필요합니다. |

## 2. 이전 리뷰(plan-review-r2) 지적 해소 여부

### 2-1. 상위 약점 R1~R5

| 지적 | 해소 여부 | 근거 |
|---|---|---|
| R1. 차량 SDK 실증 0 | 미해소 | `PleosVehicleSignalSource`는 여전히 `emptyFlow()`이고, `PleosAmbientController.apply()`는 `Log.i`, Pleos 의존성은 주석 상태입니다(`app/build.gradle.kts`). `docs/STATUS.md`에는 "Playground에서 SDK 사용 신청(아직 안 함)"이라고 적혀 있습니다. 기획서 5-4는 이 상태를 "0%"라고 정직하게 밝히지만, 사유는 여전히 "클라우드 환경에서 접근 불가"입니다. 5-2 "확인 상태" 열도 모두 "확인 중/미확인"입니다. |
| R2. 이벤트 방식 신호에서 장면 전환이 안 됨 | 해소(잔존 부분) | `MooDriveSession.tick()`을 추가했고, ViewModel이 1초마다 호출합니다(`MooDriveViewModel.kt:247`). 테스트 `event-based signals - one wiper event plus ticks changes the scene`와 `ticks advance continuous driving time to the fatigue alert`도 있습니다. **잔존**: `tick()`은 `timestampMs`만 갱신하고 `minuteOfDay`·`etaMinutes`는 마지막 이벤트 값에 고정합니다. 신호 변화가 없는 고속도로 구간에서는 노을·야간 전환과 심야 90분 기준이 멈춥니다. 수동 패널에는 "ETA −1분"·"운전 시간 +30분" 버튼이 없어, 앱에서는 피날레(ETA 25분 고정)와 2시간 경보를 시연할 수 없습니다. |
| R3. 안전·개인화 규칙 구멍 (터널 템포, 휴게소 대기, 장르 편향, 파서) | 부분 | **터널 템포 해소**: 탐침에서 128 BPM 곡(`ed1`)이 터널 진입 시 92 BPM으로 바뀌었고, 터널 직후 폭우에서는 90 BPM이 나왔습니다. **휴게소 해소**: 1분 무응답이면 닫고 30분 뒤 다시 제안합니다(탐침에서 0분·30분에 제안). 질문 중 "이 노래 좋아"는 곡 평가로 처리되고 '말하기' 버튼도 유지됩니다. **장르 대부분 해소**: 록·EDM·힙합 조합은 데모 0/6에서 9/12로 올랐습니다. 다만 클래식·앰비언트·어쿠스틱 조합은 맑은 낮 10곡 중 0곡입니다. **파서 부분 해소**: 3문장은 고쳤지만, 의미를 반대로 해석하는 문장이 남아 있습니다(4-1 참고). |
| R4. 사업성: 돈의 흐름·1단계 생존·방어 | 부분 | "누가 왜 돈을 내나"와 "멜론·Gleo가 따라 하면?" 문단, 무드 태깅 확장 계획을 넣었고 OEM 중복 줄도 삭제했습니다. 그러나 300원의 근거(비교 단가)가 없습니다. 1단계 리텐션 대책과 파트너 앱 미디어 세션 연동 가능성 검토도 없습니다. 방어 논리도 "규칙을 테스트로 검증했다"와 "음원사 비종속" 두 가지뿐입니다. 테스트로 검증한 규칙표는 복제를 막지 못하고, 장면별 반응 데이터나 OEM 계약 같은 진입장벽은 언급되지 않습니다. |
| R5. 차별성 빈틈·미구현 설계의 상태 미표기 | 해소(일부 잔존) | Android Auto + Gemini 행을 추가했습니다. 오디오 우선순위는 "(설계, 예정)", 차속·ETA·`checkXXXCapabilities`·퍼미션은 "(예정)"으로 표기했고, 7절에 "HTML 프로토타입 캡처"라고 밝혔습니다. 터널 시안도 폭우와 같은 곡(Grey Nocturne)으로 다시 찍었습니다. **잔존**: Gleo 행은 여전히 경쟁 행이고 "보완·연계"로 다시 쓰이지 않았습니다. 5-1 출력의 "재생(Media3)"과 기술 스택의 "Media3"에는 상태 표기가 없고, 5-2 FusedLocation 행은 "—"(문제없음처럼 읽힘)입니다. |

## 3. 남은 약점 상위 5개 (감점 크기 순)

### W1. 사업 구조: 1단계에서 살아남을 이유와 진입장벽이 없음 (사업성 −0.8)

- 기준 시나리오 매출은 연 3.2억 원(MAU 9만 × 300원 × 12)입니다. 2030년 누적 탑재 상한을 모수로 써도 이 정도라, 심사위원은 "사업이 되나"보다 "왜 이 규모인가"를 먼저 묻습니다.
- 1단계는 MooDrive가 로열티프리 40~56곡을 자체 재생합니다. 이 카탈로그로는 사용자가 멜론 대신 MooDrive를 켤 이유가 없습니다. 1단계 지표가 없으면 2단계 제휴 협상도 없습니다.
- 방어 논리 "규칙을 테스트로 검증해 쌓았다"는 진입장벽이 아닙니다. 장면 규칙은 11줄짜리 우선순위 표(`ContextEngine.detectScene`)입니다.
- **고칠 것**
  1. 1단계부터 자체 재생을 버리고 "**다른 미디어 앱을 지휘하는 엔진**"으로 바꿀 수 있는지 검토합니다. AAOS `MediaBrowser`/`MediaController`로 멜론의 미디어 세션에 검색·재생 요청을 보낼 수 있는지 에뮬레이터에서 확인하고, 결과(가능/불가/정책 문의 중)를 5-2에 적습니다.
  2. 과금 주체를 둘로 나눕니다. OEM 라이선스(차량 1대당 일회성 X원, Gleo 장면 API로 공급)와 스트리밍 정산(MAU당 300원)입니다. 각 단가 옆에 비교 근거 1개(예: 차량용 소프트웨어 옵션 단가 사례, 음악 추천 API 단가 사례)를 붙입니다.
  3. 진입장벽 3줄을 씁니다. (a) 차량 신호 × 스킵 반응 데이터(주행 수가 늘수록 장면별 무드 좌표가 보정됨), (b) 차량별 신호 품질 보정표(차종별 와이퍼 단계·오토라이트 특성), (c) OEM 테마 독점 계약.
  4. 연도별(2027~2030) 탑재 대수 추정을 범위로 넣어, 2,000만을 그대로 쓰는 인상을 지웁니다.

### W2. 차량 SDK 실증 0, APK·영상 없음 (기술활용성 −0.5, 차량특화성 −0.2, 가산점 0)

- SDK 호출 0개, APK 없음, 시연 영상 없음(11/12 예정)입니다. STATUS 기준 Playground SDK 신청도 아직입니다. 같은 공모전의 상위권 팀은 Virtual Console로 신호를 바꾸는 영상이나 APK를 낼 가능성이 큽니다.
- 기획서가 "0%"라고 정직하게 밝힌 점은 신뢰를 지키지만, 차량특화성 주장 전체가 "SDK가 와이퍼 단계를 준다면"이라는 가정 위에 있습니다.
- **고칠 것**
  1. 오늘 SDK를 신청합니다. 11/09까지 Wiper·LowBeam 구독과 P/D단 앰비언트 set 1회만 연결합니다.
  2. 결과를 5-2 "확인 상태" 열에 날짜와 함께 적습니다(예: "11/08 에뮬레이터: Wiper OFF/INT/LOW/HIGH 확인", "D단 set: 거부 → 정차 적용 유지"). 실패해도 적습니다.
  3. 시연 영상 첫 20초는 Virtual Console 와이퍼 조작과 15초 뒤 앱 반응을 화면 분할로 보여 줍니다.
  4. 5-4 사유를 "SDK 신청 진행 중(11/0x 신청)"으로 STATUS와 맞춥니다.

### W3. 신호 판정이 실제 도로에서 흔한 상황에 약함: 터널 오탐, 짧은 정차 (차량특화성 −0.2, 기술활용성 −0.2)

- **터널 오탐**(탐침, `ContextEngine.updateTunnel`): 규칙은 "주간 + 와이퍼 꺼짐 + 하향등 켜짐이면 최대 4분 터널"입니다.
  - 오토라이트를 켜고 빗길을 달리다 비가 그쳐 와이퍼가 꺼지면, 하향등이 계속 켜져 있으므로 그 순간부터 **245초간 TUNNEL**입니다. DJ는 "비가 그쳤네요"도 하지 않고 조용히 '터널'을 표시합니다. 바로 기획서 대표 시나리오 ①의 상황입니다.
  - 해 질 녘(일몰 25분 전)에 오토라이트가 켜져도 4분간 TUNNEL이었습니다.
  - 낮에 전조등을 켜고 다니는 운전자도 출발 후 4분간 TUNNEL이었습니다.
  - 기획서 리스크 대응("와이퍼 작동 중 하향등은 제외")은 이 경우들을 막지 못합니다.
- **짧은 정차**: P단은 즉시 판정입니다. 편의점 앞 1분 정차마다 "도착했어요", 드라이브 카드, 재출발 시 "날이 개었네요"(엉뚱한 멘트)가 나옵니다. 5회 정차하면 카드도 5장입니다.
- **고칠 것**
  1. 터널은 "하향등 OFF→ON **전환** 직전 N분 동안 와이퍼 OFF·하향등 OFF였을 때"만 후보로 삼습니다. 이미 켜져 있던 라이트에 와이퍼 OFF가 겹친 경우는 제외합니다.
  2. 보조 신호로 FusedLocation의 GPS 정확도 급락(터널의 전형적 특징)을 AND 조건으로 쓰고, 일몰 ±40분은 제외합니다. 테스트 `rain stops with auto lights on is not a tunnel`을 추가합니다.
  3. 주행 종료는 "P단 60초 이상 + (ETA ≤ 1분이거나 목적지 없음)"으로 바꾸고, 짧은 P는 '정차 중' 상태로 둡니다. 카드는 주행 1회당 1장만 만듭니다.
  4. 3절 판정 표에 "알려진 오탐과 대응" 3줄을 남깁니다. 심사위원은 오탐을 스스로 아는 팀을 더 믿습니다.

### W4. 세션 수명 결함: 데모 재생·여러 주행에서 상태가 섞임 (기술활용성 −0.2, 시연 위험 최대)

- `MooDriveViewModel.resetTrip()`은 `engine.reset()`만 부릅니다. 세션의 `log`, `lastDjAtMs`, `trackStartMs`, `tripGenre`, `drivingSinceMs`는 초기화하지 않습니다.
- **데모 두 번 재생**(탐침, 촬영 재시도나 심사 현장 재시연과 같은 조건): 두 번째 실행에서는 첫 주행의 가상 시간(10배속)이 현재 시각보다 앞서 있어 일반 멘트 간격 검사가 음수가 됩니다. 그래서 출발 인사와 **"비가 오기 시작했네요"가 빠지고**(멘트 7→5), TripEnded 로그는 9→18개로 첫 주행이 섞입니다.
- **같은 프로세스에서 두 번째 주행**: 카드 로그에 이전 주행 장면 9개가 그대로 포함됩니다(탐침에서 11개). 출발 인사 대신 "날이 개었네요"가 나옵니다.
- **피날레**: "오늘의 마지막 곡입니다"라고 한 뒤 피날레 곡이 끝나면 다른 곡이 이어집니다. 분위기 유지 중에는 무드가 그대로인데도 같은 멘트를 합니다.
- **고칠 것**
  1. `MooDriveSession.startTrip()`을 만들어 PARKED→주행 전환과 시나리오 시작 때 log·멘트 시각·곡 시작 시각·tripGenre를 초기화합니다. 시간 역행(`timestampMs < nowMs`)이 오면 기준 시각을 다시 잡습니다.
  2. 테스트 `demo replayed twice speaks the same lines`와 `second trip card contains only the second trip`을 추가합니다.
  3. 피날레는 `planFinaleQueue()`로 "피날레 곡이 도착 시각에 끝나도록" 앞 곡을 배치합니다. 또는 멘트를 "도착까지 이 분위기로 갈게요"로 바꿉니다. 유지 중이면 피날레 멘트를 생략합니다.
  4. 수동 패널에 "ETA −1분", "운전 시간 +30분" 버튼을 추가합니다. 지금은 앱에서 피날레와 2시간 경보를 시연할 방법이 없습니다.

### W5. 음성 의도의 반대 의미 오분류와 졸음 표현 누락, 빈 테스트 (기술활용성 −0.1, 안전 신뢰도 −)

  - "다음 휴게소 들르지 마" → REST_STOP(질문 중이면 **경유지 추가**)
  - "신나는 거 말고 차분하게" → MORE_ENERGY
  - "더 신나게 하지 마" → MORE_ENERGY
- 졸음 표현을 놓치는 문장: "졸린데 신나는 노래 틀어줘" → MORE_ENERGY, "피곤해"·"눈이 감겨"·"잠깐 쉬자" → UNKNOWN. 안전 기능을 내세우는 앱에서 졸음 표현을 놓치는 것은 심사에서 바로 지적될 수 있습니다.
- 가장 흔한 스킵 표현 "노래 바꿔"·"다른 노래"는 UNKNOWN입니다.
- 테스트 `tunnel entry replaces a song above the 110 bpm cap`는 전제가 맞지 않으면 `return`으로 끝나고, 실제로 매번 그렇게 끝납니다. 동작 자체는 탐침으로 맞는 것을 확인했지만, "자동 테스트로 검증"이라는 주장의 질을 떨어뜨립니다.
- **고칠 것**
  1. "A 말고 B"는 "말고" 뒤 절만 해석합니다. "~지 마/~지 말/하지 마"는 바로 앞 의도를 부정하는 규칙으로 처리합니다.
  2. 졸음 어휘(졸린·피곤·눈이 감·잠 와·쉬자)는 다른 의도보다 먼저 보고, 졸음 감지 시 음악 요청과 함께 휴게소 제안을 겹칩니다.
  3. SKIP에 "바꿔·다른 노래·다른 거"를 추가합니다.
  4. 위 문장 10개를 테스트에 넣고, 5-3에 "알려진 한계: 복합문·간접 표현" 한 줄을 남깁니다.

## 5. 2분 Q&A에서 아직 답할 수 없는 질문

1. **"에뮬레이터에서 와이퍼를 실제로 구독해 봤나요? 단계(INT/LOW/HIGH)가 나오나요?"** SDK 신청 전이라 답이 없습니다.
2. **"D단에서 앰비언트 set이 되나요? 안 되면 주행 중 '차에서만 되는 출력'은 무엇이 남나요?"** 시험 결과가 없습니다.
3. **"오토라이트를 켜고 빗길을 달리다 비가 그치면요?"** 4분 동안 '터널'이 되고 아무 말도 하지 않습니다.
4. **"편의점 앞에 1분 세우면 드라이브 카드가 뜨나요?"** 뜹니다. 정차할 때마다 뜹니다.
5. **"시연을 한 번 더 틀어 주세요."** 두 번째 재생에서는 "비가 오기 시작했네요"가 나오지 않습니다.
6. **"'마지막 곡입니다' 다음에 왜 노래가 또 나오죠?"** 피날레 큐 배치가 연결되지 않았습니다.
7. **"'다음 휴게소 들르지 마'라고 하면요? '졸린데 신나는 노래 틀어줘'는요?"** 앞 문장은 경유지 추가로, 뒤 문장은 졸음 신호 없이 템포 상승으로 처리됩니다.
8. **"1단계에서 로열티프리 50곡으로 사용자가 남을까요? 멜론 앱을 직접 지휘할 수는 없나요?"** 검토 결과가 없습니다.
9. **"Gleo가 와이퍼 신호를 받아 같은 규칙을 넣으면 MooDrive에 무엇이 남나요?"** 데이터·계약 같은 진입장벽이 정리돼 있지 않습니다.
10. **"기준 매출이 연 3.2억 원인데, 300원은 어디서 나온 숫자인가요?"** 비교 근거가 없습니다.
11. **"DJ 멘트가 '300m 앞 우회전' 안내와 겹치면요?"** 설계만 있고 코드와 플랫폼 답변이 없습니다.
12. **"스포츠 모드에서 '템포 올립니다'는 템포가 과속을 늘린다는 본인들 근거와 모순 아닌가요?"** 기획서에는 스포츠 장면이 아예 없습니다.
13. **"2시간 경보는 앱에서 어떻게 시연하나요?"** 수동 패널에 운전 시간 조절 버튼이 없고, 데모 시나리오는 30분짜리입니다.
14. **"마감까지 12일인데 SDK·APK·영상 중 하나를 포기해야 한다면요?"** 컷라인이 없습니다.
